## First fixes: journal consistency and acknowledgment persistence

Two isolated regressions reproduced defects in the existing candidate:

1. The journal accepted valid JSON with inconsistent execution evidence: empty job identity, a non-patch action, an acknowledged reservation with no result, a result belonging to another job/action, or a nonterminal result. All six cases were accepted before this change. Startup could rewrite that evidence or suppress a result instead of stopping for reconciliation.
2. A failed acknowledgment write left `Acknowledged=true` in memory even though the file had not changed. The result stopped appearing in the current process's pending reports. The server may already have persisted the result, so this does not establish server-side data loss; it is an inconsistent local persistence/retry contract.

`cmd/nodeagent/patch_journal.go` now validates every loaded entry before any recovery rewrite. Invalid evidence returns an error without changing the file.
