### What changed and why

- **P2-06:** native dpkg/RPM reports carry explicit complete-snapshot scope, collection time, count and identity digest. Atomic replacement rejects malformed, incomplete, stale, conflicting and out-of-order snapshots. An explicit complete empty snapshot differs from unavailable inventory. Fixed-boundary and removed-package reconciliation are distinct, transactionally tied to the assessment. A narrower feed cannot resolve an omitted advisory; incomplete application inventories retain historical findings. Unknown/conflicting co-installed versions block resolution; a returning package reopens its finding.
- **Publication:** PostgreSQL shared/exclusive leases and a published-generation ledger coordinate replicas. A shared filesystem guard also coordinates standalone content importers with readers. Generation includes signed sequence and expiry, even when advisory bytes are identical. Pool-pressure, cancellation and killed independent-process tests prove lock recovery for this shared-database/shared-content-root topology. Divergent roots fail closed; arbitrary deployment topologies are not certified.
- **P2-07:** dispatch captures the finding/package baseline. Execution completion separately records pending or failed verification. Later authoritative assessment advances append-only verification evidence to fixed, removed, failed or unknown. Installer success and a finding disappearing are insufficient. Duplicate, delayed and superseded reports cannot replace current evidence. Historical jobs without captured baseline/health become unknown, never retroactively green.
- **P2-08:** promotion rechecks fresh package audit, systemd service coverage, the pre-install active-service baseline, running-consumer coverage, reboot requirement and boot identity. Missing, stale, future or unhealthy evidence blocks promotion. Required reboot needs later changed boot identity. Kernel runtime mapping and unsupported application removal explicitly remain unknown. The container's missing systemd is accurately unavailable. Positive reboot/service gate transitions are isolated contract fixtures, not an actual host reboot.
- **P2-09:** snapshot, finding, assessment and verification-event changes commit together. Injected event-write failure and connection termination roll back the complete operation. Later inventory revisions, publication changes and expiry invalidate prior promotion eligibility. Successful completion requests a later full recollection. Recovery preserves the evidence tables and the existing agent journal.
- **P2-10:** installed version, repository candidate, signed repository provenance and advisory fixed boundary are separate fields. Ubuntu candidate observation verifies the installed archive-keyring signature over InRelease, Release-to-Packages digest/size and exact package/version/architecture stanza. The artifact digest is the expected digest recorded in the signed index, **not** evidence of downloading that binary. Invalid signatures, identities, credentials in URLs, stale inputs and unsupported paths yield unknown. Observations are bound to the current native snapshot and expire after one hour. The collector is bounded to 2,000 packages, 30 seconds and a 256 MiB index; unassessed cases do not become verified candidates. It does not refresh apt sources or install updates. Candidate availability does not authorize installation or enable automatic promotion.

The signed repository chain follows [Debian apt-secure](https://manpages.debian.org/testing/apt/apt-secure.8.en.html); authenticated cleartext extraction uses [GnuPG gpgv](https://gnupg.org/documentation/manuals/gnupg/gpgv.html).
